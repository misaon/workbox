# R8 — Skills ecosystems, MCP integrations, multi-agent delivery patterns, token efficiency and telemetry-for-improvement (Sept 2026)

Status: research draft, 2026-09-30. Every claim below was checked online on 2026-09-30 against official docs, specs or repos (URLs in §6). Items marked **[unverified]** could not be confirmed; star counts are as rendered on GitHub that day. "Stable" means GA in the vendor's docs; "beta/experimental" means the vendor labels it so.

## 1) Summary

- **Agent Skills (agentskills.io) is the cross-agent format.** A skill is a folder with `SKILL.md` (`name` ≤64 chars, `description` ≤1,024; optional `license`, `compatibility`, `metadata`, experimental `allowed-tools`). Adopters listed on the spec site include Claude Code, Claude, ChatGPT/Codex, Gemini CLI, Cursor, GitHub Copilot/VS Code, OpenCode, Kiro, Goose, Amp, Factory, JetBrains Junie, Roo Code and ~30 more. Progressive disclosure is built in everywhere: only name+description load at startup (~100 tokens/skill; Claude Code caps the whole listing at 1% of the context window and 1,536 chars per entry; Codex caps it at ~2% of context or 8,000 chars), the body (<5k tokens recommended, <500 lines) loads on activation, bundled files on demand.
- **Sync mechanisms that exist today:** (1) Vercel's `npx skills add <owner/repo> --skill X -a claude-code -a codex -y` (npm `skills` v1.7.0, MIT; symlinks each agent's skill dir to one canonical copy; `skills update`); (2) Claude Code plugin marketplaces (`marketplace.json`; sources github/git-subdir/url/archive(sha256)/npm; pin `ref`/`sha`; updates only when the plugin `version` changes; auto-update **off by default** for third-party marketplaces; project `.claude/settings.json` can carry `extraKnownMarketplaces` + `enabledPlugins` for teammates); (3) MCP Skills extension `io.modelcontextprotocol/skills` (SEP-2640 **Final, 2026-09-13**) — spec done, but client support is still partial and Claude Code is not in the client matrix. Plain symlinked skill folders are supported by Claude Code, and `.agents/skills/` is read by Codex, Gemini CLI and Cursor, which makes a symlink-based sync the simplest portable path.
- **Recommended collections:** obra/superpowers (MIT, 17 process skills, v6.4.2 released 2026-09-25) as the workflow backbone; a curated subset of ECC (MIT, 293 skills) for language/security packs; anthropics/skills for `skill-creator`/`mcp-builder` (Apache-2.0). Never sync whole collections: with Claude Code's 1% listing budget, more than a few dozen model-invocable skills degrades triggering (Claude Code ships `/skill-doctor` to measure this).
- **MCP is now spec 2026-07-28** (stateless, `server/discover`, elicitation via Multi-Round-Trip Requests, Tasks moved to an extension whose `input_required` state is designed for human approval gates, Roots/Sampling/Logging deprecated, `traceparent` conventions in `_meta`). Official remote servers exist for GitHub, Atlassian (v2, GA) and Slack. For the four deterministic writes Workbox needs (Jira transition/comment, PR create/merge, Slack post) CLIs (`gh`, `acli`, `slack api`) or direct REST are cheaper and more reliable than routing through an LLM tool call; Claude Code's own docs call CLIs "the most context-efficient way to interact with external services". Use MCP where OAuth/user context and structured reads matter.
- **Role separation evidence:** orchestrator + fresh-context workers pays off for parallel, read-heavy work (Anthropic research system: +90.2% over a single Opus agent, but ~15x tokens, and "token usage explains 80% of the variance"). For a single ticket, the best documented quality-per-token split is a **single-threaded implementer plus a separate fresh-context reviewer/verifier and deterministic gates** (tests, Stop hooks). Cognition's "Don't build multi-agents" and the MAST failure taxonomy both warn against parallel implementers with shared files; Agentless showed a fixed localize→repair→validate pipeline at $0.70/issue beating open-source agents of its time.
- **Telemetry:** OpenTelemetry GenAI conventions moved to a dedicated repo and are still "Development" status; Claude Code and Codex both export OTel natively (Claude Code: metrics + events stable, traces beta). Capture Workbox-level stage/handoff/approval/outcome events and keep raw transcripts; that is what GEPA-style reflective optimizers and Promptfoo/Braintrust/Langfuse evals need.

|---|---|---|

| Verification loops / deterministic gates | Anthropic long-running harness (2025-11-26): feature list, progress file, one feature at a time, e2e check; Claude Code `/goal` and Stop hooks; Ralph Wiggum plugin (`/ralph-loop "<prompt>" --max-iterations N --completion-promise "…"`) | Gate "done" on tests/build, cap iterations |

## 3) Recommended default Workbox workflow

**Roles** (each an agent definition with its own tools, model tier and preloaded skills — the pixel-art employees). Deterministic steps are code, not model turns.

1. **Dispatcher (code, 0 tokens)** — reads the ticket, transitions to In Progress (`acli`/REST), prepares a git worktree/branch, opens the run record.
2. **Analyst (small model, `effort: low`, read-only tools, Explore-style)** — reads ticket + repo; writes `brief.md`: goal, acceptance criteria, likely files, risks, open questions each with a recommended answer. Returns ≤2k tokens (Anthropic's 1–2k-token subagent summary guidance).
3. **Planner (frontier model, plan mode, read-only)** — runs only when the brief flags multi-file/ambiguous work; writes `plan.md` + `tasks.json` (spec-kit/Kiro shape). Skipped for one-liners.
4. **Implementer (frontier model, `acceptEdits`, TDD + debugging skills preloaded)** — single-threaded, one task at a time, commit per task, tests as the completion condition, Ralph-style loop bounded by max iterations.
5. **Reviewer (fresh context, read-only, may be a different harness/model)** — reviews the diff against brief/plan; reports only correctness and requirement gaps; at most two fix rounds back to Implementer.
6. **Publisher (code + small model)** — `gh pr create` with a body generated from brief + diff; posts the Slack review request; watches PR comments (webhook/poll) and resumes the Implementer as **Responder** per comment batch.
7. **Closer (code + small model)** — `gh pr merge --squash --delete-branch` once approved and green; `acli jira workitem comment-create` with PR link + tester instructions (small model, from brief + diff); `acli jira workitem transition --status Testing --yes`.

**Hand-offs** are files in the run directory (`brief.md`, `plan.md`, `tasks.json`, `review.md`, `progress.md`), never conversation history: each role starts with a clean, cache-friendly prefix, and runs survive crashes (Anthropic long-running-harness pattern). Keep model and effort fixed within a role (both are cache keys for most models).

**Approval points** (each shows a recommended option pre-selected; non-destructive ones auto-continue after a timeout, like Claude Code's `askUserQuestionTimeout`):

| Point | Question | Default |
|---|---|---|
| A1 Start | Run ticket X on branch Y? | Yes (auto when the owner triggered it) |
| A2 Plan/brief | Open questions with recommended answers; plan summary | Proceed with recommended answers; destructive choices never time out |
| A3 Open PR | Create PR (draft first?) | Yes, ready-for-review (auto) |
| A4 Slack | Ping @reviewer (CODEOWNERS / last-touched author) | Yes (auto) |
| A5 Merge | Merge now? | Ask; per-repo opt-in to `gh pr merge --auto` after approval + green CI |
| A6 Danger | force-push, branch delete, secrets in diff, non-allowlisted network | Always ask, deny by default |

Enforce with hooks, not prompts: Claude Code `PreToolUse` hooks return `permissionDecision: allow|deny|ask` (with `updatedInput`), `PermissionRequest` hooks auto-approve policy-safe calls, Stop hooks block "done" until tests pass; Codex has `approval_policy` (`on-request|never` plus granular `rules`, `skill_approval`, `mcp_elicitations`) and `sandbox_mode` (`read-only|workspace-write|danger-full-access`).

**Skills-sync approach.** Workbox keeps one canonical checkout `~/.workbox/skills/` populated from a curated manifest (`skills.manifest.json`: repo, pinned commit, skill names, target agents, content hash) via `npx skills add <repo> --skill … -y` (or `git subtree` for repos not indexed), then symlinks selected skills into `.claude/skills/` and `.agents/skills/` of the working tree (Claude Code reads symlinked skill folders; Codex, Gemini CLI and Cursor read `.agents/skills/`). A weekly `skills update` produces a diff the owner approves (default: accept when `description` unchanged; ask when it changed, because descriptions drive triggering). Workbox's own role skills ship as a Claude Code plugin marketplace pinned by `ref`, enabled per repo through `.claude/settings.json`. Initial set (~12 skills, well under the 1% listing budget): superpowers `brainstorming`, `writing-plans`, `test-driven-development`, `systematic-debugging`, `verification-before-completion`, `requesting-code-review`, `receiving-code-review`, `using-git-worktrees`, `finishing-a-development-branch`; the ECC rule pack for the repo's language; anthropics `skill-creator`. Skills with side effects get `disable-model-invocation: true`.

**Token discipline that preserves quality (all verified):** stable prefixes and 1h cache TTL on the main conversation (subscription default; subagents 5m unless `subagentPromptCacheTtl: 1h`); no model/effort switches mid-role; small models at `effort: low` for Analyst/Publisher/Closer; CLI tools instead of MCP for writes; hook-side filtering of test output (`PreToolUse` `updatedInput`); `MAX_MCP_OUTPUT_TOKENS`; compaction only at role boundaries (Claude Code re-attaches invoked skills at 5k tokens each, 25k total); server-side compaction (`compact-2026-09-04`, beta) and context editing (`clear_tool_uses_20250919`, beta) when Workbox drives the API directly.

## 4) Telemetry schema sketch

Align with OpenTelemetry GenAI conventions (repo `open-telemetry/semantic-conventions-genai`; **Development** status, names may change) and join with Claude Code/Codex native OTel via `session.id` and W3C `traceparent` (Claude Code propagates `TRACEPARENT` into the CLI and into Bash commands).

- **Trace per run:** root `workbox.run` {ticket.key, repo, branch, trigger, workbox.version}; child `workbox.stage` spans (dispatch, analyze, plan, implement, review, publish, respond, close); per role `invoke_agent {role}` spans with `gen_ai.agent.name`, `gen_ai.provider.name`, `gen_ai.request.model`, `gen_ai.usage.input_tokens/output_tokens`, cache read/creation tokens, `effort`, harness (`claude-code|codex`), `skills.loaded[]`, `transcript_ref`; `execute_tool` spans (`gen_ai.tool.name`, `mcp.method.name`, `error.type`); pass-through of Claude Code spans `claude_code.interaction → llm_request / tool (blocked_on_user, execution) / hook` (traces beta: `CLAUDE_CODE_ENHANCED_TELEMETRY_BETA=1`).
- **Events:** `workbox.handoff` {from_role, to_role, artifact, artifact_tokens, hash}; `workbox.approval` {point A1–A6, options[], recommended, chosen, decided_by human|timeout|policy, latency_ms}; `workbox.review_round` {round, findings, accepted}; `workbox.pr_comment` {author, addressed, turns}; `workbox.outcome` {merged|abandoned|escalated, ci_green, human_edits_loc_after_agent, review_comments, wall_time, tokens_total, cost_estimate}; plus Claude Code `claude_code.api_request`, `tool_result`, `tool_decision`, `api_error`, `assistant_response` (enable `OTEL_LOG_TOOL_DETAILS=1`; keep `OTEL_LOG_USER_PROMPTS`/`OTEL_LOG_TOOL_CONTENT`/`OTEL_LOG_RAW_API_BODIES` opt-in) and Codex `[otel] exporter = otlp-http|otlp-grpc`, `log_user_prompt`.
- **Metrics:** mirror `gen_ai.client.token.usage`, `gen_ai.invoke_agent.duration/inference_calls/tool_calls`, `gen_ai.execute_tool.duration`, plus `workbox.run.tokens` and `workbox.run.cost` by role/skill/model; local reconciliation with ccusage (reads `~/.claude/projects/*.jsonl`; supports Codex, Gemini CLI, Copilot CLI…).
- **Transcripts:** copy raw JSONL / Agent SDK `stream-json` into the run directory; message content (`gen_ai.input.messages/output.messages`) only with explicit opt-in.
- **Improvement loop:** export to Langfuse (OTLP `/api/public/otel`, maps `gen_ai.*`) or a local store; build Promptfoo/Braintrust datasets from failures (rejected approvals, >1 review round, post-merge human edits, abandoned runs); run a GEPA/DSPy-style reflective optimizer (GEPA: +6–20% over GRPO with 35x fewer rollouts, ICLR 2026) that proposes prompt/skill edits from trace text; land proposals as a PR to the skills manifest, never auto-apply; grade outcomes, not paths (Anthropic evals guidance).

## 5) Open questions for the owner

1. Rovo credits: does your Jira Cloud plan let the MCP server transition/comment without consuming credits? A 10-call test settles it; otherwise `acli`/REST is the path.
2. Merge policy per repo: human merge (default) or `gh pr merge --auto` after approval + green CI?
3. Harness per role: e.g. Claude Code implementer + Codex reviewer for model diversity (both on subscriptions)? Should CI-side runs use the Claude Code Action with `CLAUDE_CODE_OAUTH_TOKEN`?
4. Slack: fixed internal app with Events API (needed for reply detection) vs the MCP connector (read-only polling)?
5. Retention and content capture for the improvement loop: local-only transcripts? enable `OTEL_LOG_USER_PROMPTS`?
6. Spec-driven artifacts for every ticket, or only when the Analyst flags ambiguity?
7. Skill listing cap: hard-limit Workbox to ~12 model-invocable skills, or expose more as user-invocable only?
