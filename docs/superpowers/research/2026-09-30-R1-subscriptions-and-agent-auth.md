# R1 — Driving coding agents through the owner's existing consumer subscriptions (Claude Pro/Max, ChatGPT Plus/Pro)

Status: research draft, 2026-09-30. Every version/policy claim below was checked online on 2026-09-30; items marked **[unverified]** could not be confirmed from a primary source. "Stable"/"beta"/"experimental" labels are the vendors' own where quoted.

## 1) Summary of findings

**Anthropic (Claude Pro/Max)**

- Versions: `@anthropic-ai/claude-agent-sdk` **0.3.285** (GitHub release 2026-09-29; Node >= 18; bundles a native Claude Code binary via optional deps; peer deps `zod ^4`, `@anthropic-ai/sdk >= 0.93`, `@modelcontextprotocol/sdk ^1.29`). Claude Code CLI **2.1.285**. Both are GA/stable; several SDK methods are labelled alpha (`prewarm()`, `readMcpResource()`).
- Auth model: the SDK "runs the Claude Code binary" and inherits the binary's credential resolution. Precedence: cloud provider > `ANTHROPIC_AUTH_TOKEN` > `ANTHROPIC_API_KEY` > `apiKeyHelper` > `CLAUDE_CODE_OAUTH_TOKEN` (one-year token from `claude setup-token`, "for CI pipelines and scripts", cannot start Remote Control) > Anthropic profiles > **subscription OAuth from `/login`** (default for Pro/Max). Credentials live in the macOS Keychain or `~/.claude/.credentials.json` (0600); `CLAUDE_CONFIG_DIR` isolates accounts. **`--bare` never reads OAuth credentials** (API key only) even though Anthropic says it "will become the default for `-p` in a future release".
- Current written policy (code.claude.com/docs/en/legal-and-compliance, fetched 2026-09-30):
  - "OAuth authentication is intended exclusively for purchasers of Claude Free, Pro, Max, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications."
  - "Developers building products or services that interact with Claude's capabilities, including those using the Agent SDK, should use API key authentication ... Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, or Max plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens — sign-in to a Claude account must complete through Anthropic's own flow."
  - "Nor does it prevent an end user from signing in to the unmodified Claude Code binary with their own Claude subscription, including where a platform hosts Claude Code" and "The Claude Code binary must not be modified ... customers may not remove, disable, or restrict any authentication method built into it."
  - "Advertised usage limits for Pro and Max plans assume ordinary, individual usage of Claude Code and the Agent SDK." "Anthropic reserves the right to take measures to enforce these restrictions and may do so without prior notice."
  - Agent SDK docs add: "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK." Branding: say "Claude Agent", never "Claude Code Agent".
- Billing status (support.claude.com article 15036540, updated 2026-06-16): "Claude Agent SDK, `claude -p`, and third-party app usage still draw from your subscription's usage limits." The planned June 15 move to a separate monthly "Agent SDK credit" ($20 Pro / $100 Max 5x / $200 Max 20x, metered at API list prices, covering "Third-party apps that authenticate with your Claude subscription through the Agent SDK") was **paused**; Anthropic is "working to update the plan" and promises advance notice.
- 2026 policy history (four swings): 2026-01-08/09 server-side block of spoofed OAuth in OpenCode/Cline/RooCode ("This credential is only authorized for use with Claude Code"); 2026-02-19 legal page: "Using OAuth tokens obtained through Claude Free, Pro, or Max accounts in any other product, tool, or service, including the Agent SDK, is not permitted"; 2026-04-04 "third-party tools will draw from extra usage instead of subscription limits" (OpenClaw et al.); 2026-05-13 reversal via the credit model; 2026-06-16 pause. OpenCode's docs today: Pro/Max login "Anthropic explicitly prohibits this", removed in 1.3.0.
- Headless surface (stable): `claude -p --output-format stream-json --input-format stream-json --include-partial-messages`, `--resume <id|name|path>`, `--continue`, `--session-id`, `--fork-session`, `--permission-mode {default,acceptEdits,plan,auto,dontAsk,bypassPermissions}`, `--permission-prompt-tool <mcp tool>`, `--permission-prompts host|none` (v2.1.259+), `--replay-user-messages`, `--forward-subagent-text`, `--max-budget-usd`.
- "Asking" dialog building blocks: SDK permission flow is hooks → deny rules → ask rules → mode → allow rules → `canUseTool(toolName, input, {signal, suggestions})` returning `{behavior:'allow', updatedInput, updatedPermissions}` or `{behavior:'deny', message}`; `AskUserQuestion` also arrives through `canUseTool`; "The callback can stay pending indefinitely"; use a `PreToolUse` hook returning `defer` to persist and resume later; `PermissionRequest` hooks (incl. `type: "http"`) can route approvals to an external UI.
- Usage/limits: `/usage` is interactive-only. The endpoint Claude Code uses (`api.anthropic.com/api/oauth/usage`, header `anthropic-beta: oauth-2025-04-20`, returns `five_hour`/`seven_day` utilization) is **undocumented**, aggressively rate-limited, and requests to document it were closed "not planned" (claude-code issues #31637, #45392). Documented alternatives: SDK `accountInfo()`/`system.init.account` (subscription type), `rate_limit_event`, `system/api_retry` with `error: "rate_limit"`, result `total_cost_usd` (estimate), and local transcripts in `~/.claude/projects` (what ccusage/opcode read). One Feb-2026 report of "account action" against a usage-tracking app **[unverified, single secondary source]**.
- Remote Control (GA docs): Pro/Max/Team/Enterprise only, "API keys are not supported"; `claude remote-control --spawn worktree --capacity 32 --permission-mode ...` serves sessions to claude.ai/code and the Claude mobile app; no third-party API; overlaps with Workbox's phone story.

**OpenAI (ChatGPT Plus/Pro)**

- Versions: Codex CLI **0.159.2** (2026-09-29); `@openai/codex-sdk` **0.159.2** (Apache-2.0, Node >= 18, depends on `@openai/codex 0.159.2`, "spawns the CLI and exchanges JSONL events over stdin/stdout"). Plans: "ChatGPT Work and Codex are included in your ChatGPT Free, Go, Plus, Pro, Business, Edu, or Enterprise plan"; "Local messages and cloud chats share your plan's usage allowance"; Pro currently has no 5-hour limit (Pro 200 drops from 20x to 10x Plus on 2026-10-30; new Pro 500 **[secondary source]**).
- Auth: "Sign in with ChatGPT" (browser or `codex login --device-auth`), or API key ("standard API pricing instead of included ChatGPT plan credits"); tokens in `~/.codex/auth.json` ("Treat ... like a password"). `CODEX_API_KEY` works with `codex exec`, the TS SDK and `codex exec-server --remote`.
- `codex app-server` is the official embedding protocol ("Embed Codex into your product"): JSON-RPC 2.0 (header omitted) over stdio JSONL by default (`--listen ws://` experimental); `initialize` with `clientInfo.name` required ("identify your client for the OpenAI Compliance Logs Platform ... for enterprise use, please contact OpenAI"); `thread/start|resume|fork|list`, `turn/start|steer|interrupt`, `item/*` streaming, approvals `item/commandExecution/requestApproval`, `item/fileChange/requestApproval`, `item/permissions/requestApproval`; **`account/read`** (→ `chatgpt{email, planType}`), **`account/rateLimits/read`** (→ `primary/secondary{usedPercent, windowDurationMins, resetsAt}`, `planType`, credits), `account/updated`, `thread/tokenUsage/updated`. `account/login` kinds: `apiKey`, `chatgpt`, `chatgptDeviceCode`, and `chatgptAuthTokens` — the latter is marked in source "[UNSTABLE] FOR OPENAI INTERNAL USE ONLY - DO NOT USE". Many methods need `capabilities.experimentalApi: true`.
- Policy: OpenAI publishes **no restriction** on third-party clients using a ChatGPT login through Codex; the ChatGPT Terms of Use page returned 403 in this session **[unverified]**; secondary sources summarise it as personal, non-shared use. Better still, at DevDay (2026-09-29) OpenAI expanded **Sign in with ChatGPT (SIWC) plan usage**: "Eligible ChatGPT Plus and Pro users can use their ChatGPT plan for AI requests in participating apps"; "ChatGPT plan usage is available to all open-source partners and selected private clients" (commercial apps: "limited trial", interest form). Open-source flow: dynamic registration (`client_id=dynamic_agent_client` → issued `oaiapp_…`), PKCE loopback on 127.0.0.1, scopes `openid profile email offline_access resource.invoke chatgpt.tokens.use.direct`, access token 1 h / refresh 30 d; call `POST https://api.openai.com/v1/responses` (`store:false`, `stream:true`) **or** run app-server with `model_provider="openai_chatgpt_plan"`, `wire_api="responses"`, `env_key="ACCESS_TOKEN"`, `requires_openai_auth=false`. Constraints: "For ChatGPT Plus users, the five-hour usage limit is shared across all apps ... including private and open-source clients"; per-app weekly caps set by the user in ChatGPT settings; a self-hosted-VM guide covers moving the credential file to a remote host; UI rules ("Continue with ChatGPT", "Using ChatGPT plan", "Manage usage"). Labelled preview.

**Others (one paragraph each)**

- Gemini CLI: official docs banner "Gemini CLI was replaced by Antigravity CLI on June 18th, 2026" for free-tier and Google One (AI Pro/Ultra) users; individuals now need `GEMINI_API_KEY` (free key: 250 req/day, Flash only) or Vertex; Code Assist Standard/Enterprise keep 1,500/2,000 req/day. Gemini CLI still ships native ACP (registry 0.62.0); Paseo drives Antigravity via the `agy` CLI. Not a subscription path for Workbox.
- GitHub Copilot: Copilot SDK GA 2026-06-02 (MIT; TS/Python/.NET bundle the CLI; JSON-RPC); auth via `copilot` login, `COPILOT_GITHUB_TOKEN`/`GH_TOKEN`, GitHub App, or BYOK; "available to all existing GitHub Copilot subscribers, including Copilot Free"; billing "same model as the Copilot CLI, with each prompt being counted towards your usage allowance". Sanctioned and low-risk; Copilot ACP is public preview.
- Cursor CLI: `agent -p --output-format stream-json --stream-partial-output`, `--force`, `--resume`; auth `agent login` (browser) or `CURSOR_API_KEY` "for automation, scripts, or CI"; agent usage counts against Pro/Pro+/Ultra pools; no published stance on third-party wrappers. Available through ACP.

**Agent Client Protocol (ACP, Zed)**

- v1 is "stable"; v2 is "experimental ... still a draft". TS SDK `@agentclientprotocol/sdk` **1.5.1** (Apache-2.0). JSON-RPC 2.0; agent methods `initialize`, `authenticate`, `session/new|prompt|load|cancel`; client methods `session/request_permission`, `fs/read_text_file`, `fs/write_text_file`, `terminal/create|output|kill|wait_for_exit`, `elicitation/create`; updates carry message chunks, tool calls, plans, modes, diffs (AIR diff extension). Registry JSON at `cdn.agentclientprotocol.com/registry/v1/latest/registry.json` lists Claude Agent 0.84.0 (`@agentclientprotocol/claude-agent-acp`, built on `claude-agent-sdk 0.3.284`), Codex 2.0.1 (`@agentclientprotocol/codex-acp`, starts `codex app-server` internally; ChatGPT login or API key), Gemini CLI 0.62.0, plus 50+ agents (Copilot preview, Cursor, Cline, Goose, Kiro, OpenCode...). Subscription auth works through the adapters (Zed: "/login ... an API key or with Claude Code where supported"; Zed's May-2026 post confirms ACP usage drew from Claude subscriptions). Zed: "Billing, legal terms, retention, and data handling are between you and the agent provider." Viable as Workbox's *generic* layer; for Claude/Codex the native SDK/app-server exposes more (hooks, subagent transcripts, account/rate-limit reads).

## 3) Recommendation for Workbox

1. **Claude: Path A as the default, Path B as the interchangeable fallback, never D.** Use `@anthropic-ai/claude-agent-sdk` (TS) with `settingSources: ['user','project','local']`, `canUseTool` + `PreToolUse defer` + `PermissionRequest` hooks for the pixel-office "asking" dialog, `includePartialMessages` for streaming, `resume`/`forkSession` for employee memory, and `pathToClaudeCodeExecutable` to optionally pin the user's system `claude` (keeps `/login` state and version parity). Do **not** pass `--bare` (drops OAuth). Never read, copy or refresh Anthropic tokens; login happens in Anthropic's own flow (`claude auth login`, `claude auth status --json` to detect state). Mirror `/status` in the UI so the user sees whether a subscription or `ANTHROPIC_API_KEY` is active, and ship API-key + Bedrock/Vertex support from day one as the compliance escape hatch. Rationale: this is exactly how Paseo, Happy and Zed operate, it is the only posture Anthropic currently says still draws from the subscription, and the worst realistic outcome of the next policy swing is a monthly credit cap, not a break. Label the agent "Claude Agent".
2. **Codex: Path G (app-server over stdio) as primary, Path I as phase 2.** Implement a small JSON-RPC client (`initialize` with `clientInfo.name: "workbox"`, thread/turn/item, approvals, `account/read`, `account/rateLimits/read` for the usage meter, `thread/tokenUsage/updated`). Add the SIWC open-source flow later: it is the one path with an explicit written OK from a vendor for open-source tools and it also solves sandbox credentials (self-hosted-VM guide), at the cost of preview limitations and UI rules.
3. **Everything else through ACP (Path F)** using `@agentclientprotocol/sdk` 1.5.x as a client: Copilot, Cursor, Gemini/Antigravity, OpenCode, Kiro... This mirrors Paseo's "native adapters + generic ACP" split and keeps the pixel-office model agent-agnostic (permission requests, terminals, diffs are first-class in ACP v1).
4. **Usage display:** compute from SDK/app-server events and local transcripts; do not poll Anthropic's undocumented `/api/oauth/usage`.
5. **Sandboxes:** decide credential delivery explicitly (mount `CLAUDE_CONFIG_DIR`/`~/.codex` read-only, or user-supplied `CLAUDE_CODE_OAUTH_TOKEN`/`codex login --device-auth` inside the sandbox). Anthropic forbids the *tool* intermediating tokens, so the user must perform the login/paste, and Workbox only passes env through.

## 4) Open questions to confirm with the owner

- Accept "medium" policy risk on Claude subscription use (reversals in Jan/Feb/Apr/May/Jun 2026; a future credit cap is plausible)? Is an API-key/budget fallback UI a launch requirement?
- Sandbox strategy: run agents on the host with Claude Code's own `--sandbox`/Codex `--sandbox workspace-write`, or in containers that need credentials mounted or pasted?
- Codex: app-server with the user's existing login only, or also SIWC open-source registration (needs stable host id, loopback OAuth, credential file, OpenAI UI wording)? Does Workbox's license/hosting meet OpenAI's "open-source, locally or self-hosted" eligibility?
- Multiple Claude accounts per owner (`CLAUDE_CONFIG_DIR` per employee) — desired? Rotation tools exist but sit against "ordinary, individual usage".
- Is Claude Code Remote Control (phone control, worktree spawn, 32 sessions, Pro/Max) a competitor to design against or a feature to embed (`claude remote-control` cannot be driven by API keys or setup-tokens)?
- Gemini: drop, or support only via API key / Antigravity CLI through ACP?
