# R2 — Agent harness frameworks, SDKs and protocols for a TypeScript coding-agent orchestrator

Status: research draft, 2026-09-30. All versions, dates and feature claims below were checked online on 2026-09-30 (official docs, GitHub, npm registry). Items marked **[unverified]** could not be confirmed from a primary source. "Stable / beta / experimental" labels are the vendors' own where available.

## 1) Summary of findings

- **Zero-API-spend is the deciding constraint.** Every general agent framework surveyed (Vercel AI SDK core, Mastra, VoltAgent, LangGraph.js, Deep Agents, Google ADK, OpenAI Agents SDK, OpenAI Agents API) authenticates with API keys. Subscription-priced tokens are reachable only *through vendor harness binaries*: Claude Code (via the Claude Agent SDK / `claude -p`, policy caveats below), Codex CLI (ChatGPT sign-in is the primary, documented auth for CLI, SDK, App Server and the Codex plugin, "including the Free tier"), OpenCode (ChatGPT Plus/Pro login supported; Claude Pro/Max login removed as of 1.3.0 because "Anthropic explicitly prohibits" it), Pi (Codex OAuth labelled "legacy"; Anthropic API-key only), Gemini CLI (free Google login, 60 req/min, 1,000 req/day).
- **Claude subscription + Agent SDK is legally murky and in flux.** Anthropic's Agent SDK overview says third-party developers may not "offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK" unless approved. Yet the June 2026 support article says "Claude Agent SDK, `claude -p`, and third-party app usage still draw from your subscription's usage limits" after Anthropic paused (June 15/16, 2026) a plan to move SDK usage to separate monthly credits ($20 Pro / $100 Max 5x / $200 Max 20x). Third-party OAuth spoofing (OpenCode, OpenClaw) was blocked in Jan–Apr 2026. Owner-only, local use of the SDK is the least risky path; Workbox must not ship "log in with Claude". Defer the final call to the auth/ToS research track.
- **Claude Agent SDK for TypeScript is the richest harness API** (`@anthropic-ai/claude-agent-sdk` 0.3.285, 2026-09-29, tracks Claude Code v2.1.285; daily releases). Verified: programmatic subagents (`agents`, per-agent `model`/`effort`/`tools`/`background`/`memory`), hooks (incl. `PreCompact`, `SubagentStart/Stop`), in-process MCP tools (`createSdkMcpServer`/`tool`), plugins, skills, `resume`/`forkSession`/`sessionStore`, streaming input (`streamInput`) and partial output, `canUseTool` + six permission modes (incl. `auto` classifier), structured output (`outputFormat: json_schema`), `effort: low|medium|high|xhigh|max` + adaptive thinking, `maxTurns`/`maxBudgetUsd`, automatic compaction and prompt caching, MCP tool-search deferral, `getContextUsage()`, `onElicitation`, `Workflow` tool (dynamic workflows, GA May 28, 2026), `spawnClaudeCodeProcess` for containers. Alpha: `prewarm()`, `taskBudget`, `readMcpResource` (MCP Apps). Not open source (Anthropic Commercial Terms). **Agent teams are interactive-only and do not run in `-p`/SDK sessions**; Remote Control requires claude.ai subscription auth (not API keys).
- **Codex is now integration-first.** `@openai/codex-sdk` 0.159.2 (Apache-2.0) wraps the Rust CLI (127.4k stars) over JSONL; the **Codex App Server** (JSON-RPC 2.0 over stdio, stable; WebSocket experimental; unix socket) exposes `thread/start|resume|fork`, `turn/start|steer|interrupt`, approval requests, item streaming, MCP, skills and `codex app-server generate-ts` for typed clients. `codex mcp-server` was removed in v0.149.1 (Aug 24, 2026). Config knobs: `model_reasoning_effort` (low…ultra), `model_auto_compact_token_limit`, `tool_output_token_limit`, `agents.max_concurrent_threads_per_session`.
- **Vercel AI SDK 7 (June 25, 2026; `ai` 7.0.123) validates the "harness adapter" idea**: experimental `HarnessAgent` + `HarnessV1` adapters `@ai-sdk/harness-claude-code`, `-codex`, `-pi`, `-opencode`, `-acp`, `-deepagents`, `-cline`, `-cursor`, `-github-copilot`. But the adapters run a *bridge process inside a sandbox* (Vercel Sandbox-centric, WebSocket to host, "caller owns the sandbox lifecycle"; ACP adapter maps Codex permissions to `allow-all` only). Good design reference, poor fit as a local-first dependency today.
- **ACP (Zed) is the neutral wire protocol for the "developer" role.** v1 stable (`@agentclientprotocol/sdk` 1.5.1, Apache-2.0), v2 draft; registry with 70+ agents (Jan 28, 2026); native: OpenCode, Gemini CLI, Copilot CLI, Goose, Cline, Cursor, OpenClaw; adapters: Claude (`claude-agent-acp`, built on the Agent SDK, 2.6k stars), Codex (`codex-acp`, built on App Server, 420 stars), Pi (`pi-acp`). Many mobile ACP clients already exist (Happy, Mobvibe, Runmote).
- **MCP 2026-07-28 is a breaking redesign**: stateless (no `initialize`, no `Mcp-Session-Id`), server-initiated `elicitation/create`/`sampling` replaced by **MRTR** (`resultType: "input_required"`), Tasks moved to extension `io.modelcontextprotocol/tasks`, Roots/Sampling/Logging deprecated, HTTP+SSE deprecated, official extensions for **MCP Apps** (`io.modelcontextprotocol/ui`) and **Skills over MCP** (SEP-2640 Final). TS SDK v2 = `@modelcontextprotocol/server` 2.2.0 / `client`; v1 `@modelcontextprotocol/sdk` 1.31.0 still maintained. The Claude Agent SDK still peer-depends on the v1 SDK (`^1.29.0`).
- **Agent Skills (SKILL.md) is the de-facto cross-harness instruction format** — supported by Claude Code, Codex, Gemini CLI, OpenCode, Pi, Cursor, Copilot, Goose, Amp and more — so one Workbox skills folder can drive every employee regardless of vendor.
- **Prior art is crowded and converging on the same design**: Paseo (19.1k stars, Apache-2.0, TS daemon + Electron + Expo iOS/Android, drives Claude Code/Codex/Copilot/OpenCode/Pi via their own CLIs and native credentials), Emdash (5.9k, Electron), Symphony (OpenAI, 27.5k, spec + Elixir reference), Vibe Kanban (28.2k, **sunsetting**), Conductor, Mux, Pragma. Differentiators left for Workbox: the office metaphor, cheap coordinator roles, and cross-vendor skills/MCP tooling.

## 4) Recommendation for Workbox

**Choose the hybrid (option 3), but redefine "lightweight framework": under zero API spend there is no framework tier — coordinator/planner roles must also run inside subscription-authenticated harnesses, just configured cheaply.**

1. **Developer role = harness adapters behind a Workbox-owned `HarnessAdapter` interface.** Model it on the verified primitives common to Claude Agent SDK, Codex App Server and ACP: `createSession/resume/fork`, `sendTurn/steer/interrupt`, normalized event stream (AG-UI-style), `permissionRequest` callback, `usage/cost`, and knobs `{model, effort, permissionMode, cwd, mcpServers, skills}`. Ship adapters in this order: (a) **Claude via Claude Agent SDK** (richest: hooks, `canUseTool`, `outputFormat`, budgets, `sessionStore`), (b) **Codex via App Server** (steer/fork/typed schema; ChatGPT login is officially supported), (c) **generic ACP v1** (instantly adds OpenCode, Gemini CLI, Copilot CLI, Goose; also a fallback path for Claude/Codex), (d) optional OpenCode HTTP/SSE server for plugin-hook depth. Do not build on `@ai-sdk/harness` yet (experimental, sandbox-bridge-centric), but keep its adapter spec as a compatibility target.
2. **Coordinator/planner/reviewer roles = the same harnesses in "cheap mode".** Claude Agent SDK `query()` with `effort: "low"|"medium"`, small model alias, `tools` restricted to Workbox's MCP tools, `maxTurns`/`maxBudgetUsd`, `outputFormat` for machine-readable plans, `omitClaudeMd`; or Codex threads with `model_reasoning_effort = low` and `read-only` sandbox. Alternate vendors per role so one subscription's rate limits are not the bottleneck.
3. **Give agents Workbox capabilities via MCP, not vendor plugins.** One in-process/stdio MCP server (task board, mailbox, status updates, ask-owner via MRTR elicitation) mounted through `createSdkMcpServer` (Claude), `mcp_servers` (Codex), `mcpServers` at `session/new` (ACP), `opencode.json` (OpenCode). Author role instructions as **Agent Skills** so they load identically everywhere.
4. **Reuse first-party features instead of re-implementing:** Claude subagents (depth default 3, concurrency 20, spend caps) and dynamic workflows work through the SDK; agent teams do not. Claude's Remote Control and cross-session messaging (`ListAgents`/`SendMessage`, works in `-p` sessions) can coexist with Workbox's own phone control; Codex's `turn/steer` gives mid-turn redirection.
5. **Isolation stays Workbox's job**: Pi has no permission system; Claude SDK has `sandbox`/`spawnClaudeCodeProcess`; Codex has `sandbox_mode`; ACP delegates permissions to the client. Run each employee in a worktree + container regardless of harness.

Rationale: options (1) and (2) each fail one hard constraint — pure black boxes cannot express cheap, structured coordinator roles or in-process tools, while a general framework cannot spend subscription tokens. The hybrid keeps every token on a subscription path, keeps Workbox vendor-neutral through ACP/MCP/Skills, and still exploits the two vendors' deepest APIs where the owner already pays.

## 5) Open questions for the owner

1. Is running the **Claude Agent SDK under a Pro/Max login for personal, local use** acceptable given Anthropic's contradictory statements (overview note vs. June 2026 support article vs. paused credit plan)? Fallback if not: Claude only via interactive `claude` (Remote Control/cross-session messaging) and Codex/OpenCode/Gemini via adapters.
2. Do you want **ACP as the primary interface** (maximum vendor coverage, thinner features) or **native SDKs first** (Claude/Codex depth) with ACP as the generic fallback?
3. Should Workbox target **MCP 2026-07-28 (v2 SDK)** for its own server while Claude Agent SDK still peers on MCP v1 — i.e., maintain two server builds, or stay on v1 until Anthropic upgrades?
4. Is **Gemini CLI's free tier** an acceptable third "employee" (Google account, 1,000 req/day), or strictly Claude + ChatGPT?
5. Which existing orchestrator (Paseo, Emdash, Symphony) should be studied or forked for the daemon/mobile layer versus building from scratch?
6. Do you accept **AG-UI** as the UI event format (external standard) or prefer a bespoke schema for the pixel-art office?
